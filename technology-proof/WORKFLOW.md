# 可重製的技術品牌影片流程

基準成片：`director-cut/output/tsmc-scale-of-possibility.mp4`，28 秒、1920×1080、30 fps。使用者已確認滿意。主路線是 **Remotion + Three.js + FFmpeg**；HyperFrames 與 Diffusion Studio 是先前獨立實驗，沒有加入這支成功成片。不要為湊工具數量改變路線。

## 1. 建立本次製作契約

複製 `templates/BRIEF.md` 到新的專案資料夾；指定受眾、片長、語言、核心問題、影片資訊截止日、發布位置。保留已核准作品，所有新版本使用獨立 composition、素材路徑與輸出名稱。

## 2. 先研究，再寫結論

優先官方新聞稿、技術頁、法說會逐字稿與投影片。保存 URL、存取日期與原始內容；每個量化說法記錄比較基準、條件、量產狀態。分開「已量產」「預計量產」「研究概念」。實際看過的影片影格與只取得逐字稿的來源分開記錄。不得宣稱看過無法播放的內容。

成本模型必須可以重算：晶片節電比例不等於整台伺服器節電比例，更不等於總持有成本。明列功率、使用率、時數、電價與適用範圍；示意假設永遠標示為估算。沒有公開晶圓報價、良率與設計成本時，不宣稱整體成本下降多少。

## 3. 故事與美術

一個連續主體帶領觀眾：晶圓 → 晶粒 → 結構 → 系統 → 使用價值。每個鏡頭回答一個問題，不以大量資訊卡取代動態敘事。碳黑、金屬銀、台積電紅、暖白收尾；中文留足閱讀時間。先寫完整逐秒分鏡，定義畫面因果、鏡頭、文字、音樂事件與事實來源。技術幾何標為概念示意，不能暗示真實製程截面。

## 4. 實作路線

- Three.js：需要真實景深、金屬反射、鏡頭環繞與結構拆解的鏡頭。
- Remotion：逐格時間軸、字體、數據圖形、字幕、轉場、音訊與可重現輸出。
- FFmpeg：音訊 mastering、封裝、抽幀、解碼檢查及必要的局部重製接合。
- 可用原始專案：`../director-cut/src/World.tsx`、`Film.tsx`、`scripts/`。複用材質與節奏語彙，不能直接沿用舊片文案冒充新解說。

固定版本由 `../package-lock.json` 管理。執行 `npm ci --cache /workspace/.cache/npm`；Python 依 `../director-cut/requirements.txt` 安裝。Chromium `/usr/bin/chromium`，無 GPU 環境用 `gl: 'swangle'`；`angle` 與 `swiftshader` 曾失敗。原作使用 full-resolution FXAA，最終輸出必須原生 1080p / 30fps。

## 5. 品質閘門（依序，不可跳過）

1. **事實**：每個數字有來源或可重算的估算；旁白、字幕、圖表基準一致。
2. **靜幀**：檢查每個主要鏡頭，文字清晰、材質層次、負空間與品牌一致。
3. **動態**：預覽物體交接與所有轉場。物件必須離開鏡頭後才隱藏，不能硬切消失。檢查圖表、標籤、訊號先後關係。
4. **完整預覽**：看片頭到片尾，確認資訊讀得完、音畫同步。低解析預覽不能當成品。
5. **最終編碼**：抽查真正 MP4，而不是只看原始 canvas。驗證解析度、fps、總影格、時長、全片解碼、黑畫面、音訊長度／峰值與頭尾。
6. **網站**：桌機與手機可播放、可拖曳、可開聲音、無水平溢位；驗證正式 URL 的 HTTP 200、Range 206 與檔案雜湊。

## 6. 已發生過的問題與修正

- 高曝光／大面積 bloom 讓金屬變成白塑膠：減少燈光，保留暗部與窄反射。
- 交接晶粒太小：在交接時加入相機近景，不只改字幕。
- 地板遮蔽晶圓：關掉不必要的地板；後續延长退出距離，確認晶圓完全出鏡才隱藏。
- 每三格取一格的 Remotion 預覽曾縮短音訊：預覽重新附上完整配樂；最終逐格渲染，仍需檢查音軌時長。
- 完整軟體 3D 渲染耗時：先過靜幀與動態閘門，再做 full render。局部修正可以原生重渲染後逐格接合，但記錄接點並驗證影格與音訊。
- 原作音訊 target -16 LUFS，實測 -14.6 LUFS / -1.5 dBTP；報告實測值，不把 target 當成測量結果。

## 7. 保存與發布

保存 brief、來源帳、成本模型、劇本、原始碼、鎖定依賴、字體授權、音樂事件、render logs、抽幀、QA 結果。將來源打包成 ZIP。發布到既有 GitHub Pages 時，保留過往作品，用目前遠端 gh-pages tip 作為 parent，禁止 force push。發布後重新測試正式網址。

成功標準：技術敘述可靠，普通觀眾看得懂，物體與鏡頭連貫，最後交付可播放的成片及可重做的證據。工具數量不是品質指標。

## 構圖節奏與參考證據（2026-10-04 修訂）

單張漂亮不代表整片有節奏。完整渲染前，將各章與章內鏡頭排成 contact sheet；檢查文字錨點、主體大小、視角、明暗、資訊密度是否重複。連續使用相同構圖必須有內容上的理由，不能把換文案當作新鏡頭。文字位置應讓觀眾看清楚正在解釋的結構；數值比較可以成為全畫面的主體。

參考研究區分「逐字稿讀取」「原作抽幀」「完整影片觀看」，不得混稱。YouTube 若無法取得，先記錄實際錯誤，再尋找合輯作者所介紹作品的官方原作。保存來源 URL、下載雜湊、抽幀時間與可見特徵；明確區分原作觀察和自行改編。沒有取得整支合輯，就不能宣稱看過所有示範。第三方研究影片不自動成為可重製的成片素材。

- 淺色 SVG 圖解在 Chromium 連續輸出曾出現局部圖塊重影，而單張 PNG 沒有。改 PNG 或單工未完全消除；該段改為 Python/Pillow 原生逐格繪製再以 OffthreadVideo 合成，並對全部 270 格的重影區域檢測。不要只信靜幀或「可解碼」測試。
